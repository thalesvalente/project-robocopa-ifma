# Plano técnico — Feature 000

Usar JSON como backlog macro canônico, Markdown como projeção e Python 3.11+ para geração e testes sem dependências extras. Publicação pelo conector GitHub, branch de fundação e PR; nenhum force push.

Obter Specify CLI do commit oficial fixado usando uvx. Inicializar generic e scripts Python em diretório temporário. Fazer preflight completo de origem/destinos antes de copiar; preservar a constituição. A estratégia deve falhar explicitamente em conflito, não forçar a atualização.

O ambiente desta conversa não conseguiu resolver GitHub/PyPI. O workflow GitHub-hosted é uma alternativa de execução técnica autorizada no repositório; não é um runner na máquina do usuário. Somente caminhos permitidos podem entrar no commit gerado. Nenhum segredo personalizado é necessário.

Testes: IDs, contagem, campos, estados, dependências, ciclos, ausência de evidência, lock oficial, flags sem overwrite, preservação, conflitos, repetição, arquivos obrigatórios, symlinks e projeções Markdown. Registrar o run real e verificar a publicação antes de atualizar estados finais.
